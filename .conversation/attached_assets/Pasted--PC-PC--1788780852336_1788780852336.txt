# 웹앱 개발 요청 — 소리담

스마트폰, 태블릿 PC, PC에서 주변의 소리를 손쉽게 녹음하고, 저장하고, 편집하고, 여러 소리를 조합할 수 있는 웹앱 **「소리담」**을 개발해 주세요.

최종 목표는 전체 소스코드를 GitHub 저장소에 업로드하고, 실제 URL로 접속할 수 있도록 배포하는 것입니다.

핵심 기능은 단순하게 다음 3개로 구성합니다.

1. 소리 녹음
2. 나의 소리
3. 소리 이야기

기능을 과도하게 확장하지 말고 이 세 가지 흐름을 쉽고 안정적으로 구현하는 데 집중해 주세요.


# 1. 전체 사용자 흐름

사용자가 앱에 접속하면 다음 3개의 주요 기능을 바로 선택할 수 있어야 합니다.

[ 소리 녹음 ]
소리를 녹음하고 들어보고 편집합니다.

[ 나의 소리 ]
저장한 소리를 다시 듣고 관리합니다.

[ 소리 이야기 ]
저장한 여러 소리를 배치하여 하나의 소리 이야기를 만듭니다.

모바일에서는 하단 내비게이션을 사용해도 좋습니다.

예:

녹음 | 나의 소리 | 소리 이야기


# 2. 소리 녹음

스마트폰이나 태블릿 PC의 마이크를 이용해 주변의 소리를 바로 녹음할 수 있어야 합니다.

필수 기능:

- 마이크 권한 요청
- 녹음 시작
- 녹음 일시정지
- 녹음 다시 시작
- 녹음 종료
- 현재 녹음 시간 표시
- 녹음 중임을 명확하게 표시
- 녹음 완료 후 바로 재생
- 재생 / 일시정지
- 처음부터 다시 듣기
- 다시 녹음
- 간단한 소리 편집
- 다운로드
- 나의 소리에 저장

가능하다면 녹음 중 현재 입력되는 소리를 간단한 파형 또는 오디오 레벨로 보여 주세요.

단, 시각 효과보다 녹음 안정성을 우선합니다.


# 3. 녹음한 소리 편집

녹음한 소리는 저장하기 전에 간단하게 편집할 수 있어야 합니다.

필수 기능:

- 앞부분 자르기
- 뒷부분 자르기
- 필요한 구간만 남기기
- 편집 결과 미리 듣기
- 원본으로 되돌리기

전문 오디오 편집 프로그램처럼 복잡하게 만들지 마세요.

파형을 보여주고 시작점과 끝점을 손가락으로 움직이는 정도의 직관적인 방식이면 좋습니다.

스마트폰 터치 환경에서도 편하게 사용할 수 있어야 합니다.


# 4. 소리 다운로드

녹음하거나 편집한 소리를 기기에 다운로드할 수 있어야 합니다.

예:

[ 다운로드 ]

다운로드 파일 이름은 가능한 경우 사용자가 붙인 소리 이름을 활용합니다.

예:
문닫히는소리.wav
연필굴러가는소리.wav

브라우저별 녹음 포맷 차이를 고려해 구현하고, 편집 후 결과 파일은 가능하면 WAV 등 범용성이 높은 형식으로 내보내 주세요.


# 5. 나의 소리에 저장

녹음한 소리에 사용자가 직접 이름을 붙일 수 있어야 합니다.

예:

소리 이름
[ 연필이 굴러가는 소리 ]

[ 나의 소리에 저장 ]

저장하면 앱을 닫거나 새로고침해도 소리가 유지되어야 합니다.

회원가입이나 로그인은 사용하지 않습니다.

모든 데이터는 기본적으로 사용자의 기기에 로컬 저장합니다.


# 6. 로컬 데이터 저장

사용자 경험에서는 단순히 '기기에 저장'되는 방식으로 보이게 해 주세요.

오디오 파일은 용량 때문에 일반 localStorage에 Base64 형태로 저장하지 않는 것을 권장합니다.

구현은 다음과 같이 해 주세요.

- 오디오 Blob: IndexedDB
- 소리 이름 및 메타데이터: IndexedDB 또는 localStorage
- 사용자에게는 기술적인 저장 방식이 노출되지 않음

새로고침하거나 브라우저를 다시 열어도 저장한 소리가 유지되어야 합니다.

서버나 데이터베이스는 기본 기능에 필요하지 않습니다.


# 7. 나의 소리

사용자가 저장한 모든 소리를 한눈에 볼 수 있는 화면입니다.

각 소리는 카드 형태로 표시합니다.

카드에는 최소한 다음 내용을 보여 주세요.

- 소리 이름
- 재생 버튼
- 재생 시간
- 저장 날짜 또는 생성 시각

예:

┌────────────────────────┐
 연필이 굴러가는 소리
 ▶  ━━━━━━━━━  00:03

 [편집] [다운로드] [삭제]
└────────────────────────┘

각 소리에서 다음 기능을 사용할 수 있어야 합니다.

- 재생
- 일시정지
- 이름 변경
- 다시 편집
- 다운로드
- 삭제
- 소리 이야기에 추가


# 8. 나의 소리 관리

저장된 소리가 많아져도 사용하기 어렵지 않도록 합니다.

가능하면 다음 기능을 지원합니다.

- 최신순 정렬
- 이름순 정렬
- 소리 이름 검색

다만 폴더, 태그, 카테고리 등 복잡한 관리 기능은 첫 버전에서는 만들지 않아도 됩니다.


# 9. 소리 이야기

'나의 소리'에 저장되어 있는 여러 소리를 가져와 하나의 이야기처럼 배치할 수 있는 기능입니다.

예:

소리 이야기 이름
[ 어느 날 교실에서 ]

[ 소리 추가 ]

저장된 소리 목록에서 원하는 소리를 선택해 추가합니다.


# 10. 소리 배치 방식

선택한 소리를 시간 순서대로 자유롭게 배치할 수 있어야 합니다.

기본적으로 시간은 왼쪽에서 오른쪽으로 흐릅니다.

예:

0초        5초        10초        15초

연필
[ 사각사각 ───── ]

책
          [ 사락사락 ─── ]

문
                       [ 쾅 ]

소리 블록을 움직여 시작 위치를 변경할 수 있게 합니다.

모바일에서 손가락으로 쉽게 이동할 수 있어야 합니다.


# 11. 여러 소리 겹치기

소리를 단순히 순서대로 이어 붙이는 것뿐 아니라 동시에 재생할 수도 있어야 합니다.

예:

0초        5초        10초

비 소리
[ ───────────────── ]

발소리
       [ ───── ]

문 여는 소리
                   [ ─ ]

이처럼 여러 소리를 서로 다른 줄에 놓아 겹쳐 재생할 수 있어야 합니다.


# 12. 소리 이야기 기본 편집 기능

각 소리 블록에 다음 기능을 제공합니다.

필수:

- 이동
- 시작 위치 변경
- 삭제
- 재생
- 볼륨 조절
- 앞뒤 자르기
- 복제

가능하면:

- Fade In
- Fade Out

단, 전문 DAW처럼 복잡한 인터페이스는 만들지 마세요.


# 13. 소리 이야기 전체 재생

[ 처음부터 듣기 ]

버튼을 누르면 배치해 둔 모든 소리가 설정된 시간과 위치에 맞게 재생되어야 합니다.

재생 중에는 현재 위치를 알 수 있도록 간단한 플레이헤드를 표시해 주세요.

기능:

- 전체 재생
- 일시정지
- 처음으로
- 현재 재생 위치 표시


# 14. 소리 이야기 저장

사용자가 만든 소리 이야기도 로컬에 저장할 수 있어야 합니다.

사용자가 이야기 이름을 입력합니다.

예:

[ 연필과 책의 하루 ]

저장해야 할 정보 예:

- 이야기 ID
- 이야기 이름
- 사용한 소리
- 각 소리의 위치
- 시작 시간
- 종료 시간
- 볼륨
- 자르기 정보
- 생성일
- 수정일

앱을 닫고 다시 접속해도 기존 소리 이야기를 다시 열어 편집할 수 있어야 합니다.


# 15. 소리 이야기 목록

사용자가 저장한 소리 이야기를 볼 수 있는 화면을 제공합니다.

예:

나의 소리 이야기

▶ 비 오는 교실
▶ 연필과 책의 하루
▶ 밤의 학교

각 이야기에서

- 열기
- 재생
- 이름 변경
- 편집
- 삭제

가 가능해야 합니다.


# 16. 완성된 소리 이야기 다운로드

배치한 모든 소리를 하나의 오디오 파일로 합쳐 다운로드할 수 있어야 합니다.

예:

[ 이야기 듣기 ]

[ 오디오로 만들기 ]

[ 다운로드 ]

여러 소리가 겹쳐 있는 경우에도 실제 재생 결과와 동일하게 하나의 오디오 파일로 렌더링해야 합니다.

Web Audio API와 OfflineAudioContext 등을 활용하는 방식을 검토해 주세요.

가능하면 최종 결과물은 WAV 파일로 생성합니다.


# 17. 핵심 데이터 구조

Sound 예시:

{
  id,
  name,
  audioBlob,
  duration,
  mimeType,
  createdAt,
  updatedAt
}

SoundStory 예시:

{
  id,
  title,
  clips,
  createdAt,
  updatedAt
}

SoundClip 예시:

{
  id,
  soundId,
  startTime,
  trimStart,
  trimEnd,
  volume
}

구현 과정에서 더 적절한 구조가 있다면 개선해 주세요.


# 18. 디자인 방향

전체 디자인은 단순하고 가볍게 구성합니다.

키워드:

- 미니멀
- 직관적
- 친근함
- 높은 가독성
- 충분한 여백
- 큰 터치 영역
- 모바일 우선

너무 유아적이거나 장식적인 디자인은 피합니다.

소리와 관련된 파형을 주요 시각 요소로 사용할 수 있습니다.

한국어 폰트는 Pretendard를 우선 사용합니다.

버튼에는 아이콘만 표시하지 말고 가능한 경우 텍스트를 함께 표시합니다.

예:

● 녹음하기
▶ 들어보기
✂ 편집하기
↓ 다운로드


# 19. 모바일 우선

스마트폰과 태블릿 PC 사용을 가장 중요하게 고려합니다.

주요 테스트 환경:

- iPhone Safari
- iPad Safari
- Android Chrome
- Windows Chrome
- Chromebook Chrome

모든 주요 기능은 마우스 없이 터치만으로 사용할 수 있어야 합니다.

특히 다음 기능을 확인해 주세요.

- 녹음
- 파형 이동
- 자르기
- 소리 블록 이동
- 볼륨 조절
- 소리 이야기 편집


# 20. 녹음 기술

MediaRecorder API를 기본으로 검토합니다.

브라우저별 지원 MIME type이 다르므로 특정 포맷을 하드코딩하지 마세요.

MediaRecorder.isTypeSupported() 등을 활용하여 현재 브라우저에서 사용할 수 있는 포맷을 선택하도록 구현합니다.

마이크 접근이 불가능한 경우 사용자에게 이유와 해결 방법을 보여 주세요.


# 21. 권한 오류 처리

마이크 사용 전 다음과 같이 안내합니다.

“소리를 녹음하려면 마이크 사용을 허용해 주세요.”

마이크 권한이 거부된 경우:

“브라우저 설정에서 마이크 권한을 허용한 뒤 다시 시도해 주세요.”

다음 상황도 처리해 주세요.

- 마이크가 없는 경우
- 녹음 시작 실패
- 오디오 디코딩 실패
- 저장 공간 부족
- 다운로드 실패
- 손상된 녹음 데이터


# 22. 권장 기술 스택

# 30. 완료 기준

다음 시나리오가 실제 배포된 웹사이트에서 정상 동작해야 합니다.

사이트 접속
→ 소리 녹음
→ 녹음 종료
→ 바로 재생
→ 필요한 앞뒤 부분 편집
→ 소리 이름 입력
→ 나의 소리에 저장
→ 페이지 새로고침
→ 저장한 소리가 그대로 남아 있음
→ 다시 재생
→ 다운로드
→ 여러 개의 소리 저장
→ 소리 이야기 생성
→ 저장한 소리 여러 개 불러오기
→ 원하는 시간 위치에 배치
→ 일부 소리는 순서대로 재생
→ 일부 소리는 동시에 겹쳐 재생
→ 전체 이야기 재생
→ 소리 이야기 저장
→ 다시 열어 편집
→ 가능하다면 하나의 오디오 파일로 생성
→ 다운로드

구현 완료를 보고하기 전에 반드시 다음을 확인해 주세요.

- npm install
- npm run build
- 테스트 통과
- 모바일 레이아웃
- 실제 마이크 녹음
- 오디오 재생
- 편집
- IndexedDB 저장
- 새로고침 후 데이터 유지
- 다운로드
- 소리 이야기 배치
- 여러 소리 동시 재생
- 배포 환경 동작

검증하지 않은 기능을 완료했다고 표시하지 마세요.
